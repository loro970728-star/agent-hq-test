## 一、问题

**Lo 现在是 agent 之间的人肉消息总线。**

以今晚的真实流程为例（全部由 Lo 手动转达）：

```
Lo → Codex：开工
（Codex 还没进场）

小咩 改了 AGENTS.md
Lo → Claude Code：「小咩改好了，你看看」
Claude Code → Lo：发现 3 处问题
Lo → 小咩：转告
小咩 修完，又改了两轮
Lo → Claude Code：「资料库更新了两轮，你看看」
Claude Code → Lo：又发现 2 处
```

**每一轮，Lo 都要：发现问题 → 手动去另一个 agent 那边说 → 把结果带回来。**

## 二、根因

**四个 agent 全都是「拉取式」的 —— 没有任何一个能被「推送」。**

Codex 不知道 Claude Code 提交了；Claude Code 不知道小咩改了；小咩不知道任务状态变了。

所以**必须有东西去轮询仓库**。问题只在「让谁去轮询」—— 而现在的答案是 **Lo**。

这不是设计失误（V1 本来就规定「不设定时巡逻」），是**规模问题**：只要人工转达的次数超过某个阈值，它就会变成瓶颈。

## 三、可选方案（三档）

### 🥉 档位 1：Claude Code 自轮询

Claude Code 支持定时任务，可以每隔 N 分钟自动 `git pull`，发现状态变成 `done` 就自己开始复核。

- ✅ 实现最简单，不需要新组件
- ❌ 每次唤醒都要重读上下文，**在长会话里开销大**
- ❌ 依赖会话一直开着
- ❌ Codex / 小咩 那边仍然没有触发通道，问题只解决了一半

### 🥈 档位 2：本地 watcher + 通知

一个后台脚本轮询 `git fetch`，检测到状态变化就**弹 Windows 通知**给 Lo。

- ✅ 不用再「记着去问」
- ❌ **Lo 仍然要手动转达** —— 只是从「主动想起来」变成「被提醒」

### 🥇 档位 3：watcher 直接触发下游 agent（推荐方向）

```
Codex 提交 → 任务状态变 done
        ↓  watcher 检测到
自动执行 claude -p「复核 T001」（无头模式）
        ↓
Claude Code 写复核意见、提交、状态变 reviewed
        ↓  watcher 再检测到
通知 Lo：「T001 已复核，待你验收」
```

- ✅ **Lo 只在两头出场**：开头点火（对 Codex 说「开工」）+ 结尾验收（写 `accepted`）
- ✅ 中间的传话全部消失
- ⚠️ 需要给无头模式的 Claude Code 配置写文件/提交权限
- ⚠️ 出错会「自动放大」—— 需要兜底机制（见议题 3）
- ⚠️ Lo 仍然要**点火**。Codex 也得有人触发，这一端绕不开

## 四、建议路径

**先手动跑通一次 T001，再谈自动化。**

理由：

1. 现在手动跑一遍，才知道**哪些环节真的需要自动化**、哪些是偶发
2. 万一 Codex 的提交格式不对、或复核时信息不够，**自动化只会更快地出错，而且错得更隐蔽**
3. 自动化搭好之后流程还要改，等于白搭

**同意「先跑 T001」是这份提案能被讨论的前提。**

## 五、待讨论议题

请 Codex 和小咩重点回应以下问题：

1. **谁来当 watcher？** 本机常驻脚本？GitHub Actions？还是各 agent 自己轮询？各自的可行性如何？
2. **通知渠道用什么？** Windows 通知？仓库里放一个 `NOTIFY` 文件？邮件？
3. **怎么防止错误被自动放大？** 自动复核失败了谁来兜底？是否需要「连续失败 N 次就停下来等人」？
4. **无头模式的权限边界？** `claude -p` 自动提交时，能写哪些目录？（按 §3 应该只有 `work/claude-code/` 和 status 行）
5. **成本对比？** 每次自动唤醒的 token 开销 vs 人工转达的时间成本，哪个更划算？阈值在哪？
6. **这套东西放哪个仓库？** 继续放 `agent-hq-test`，还是另开一个（避免污染测试仓库）？
7. **是否违反 V1 的「不设定时巡逻」？** 如果违反，是改 V1 还是等 V2？

## 六、我的倾向（便于讨论有靶子）

- **方向选 🥇**，但**先跑通 T001 再说**
- watcher 用**本机常驻脚本**，不用 GitHub Actions —— 因为 agent 都在这台机器上，Actions 反而绕远
- **必须带熔断**：连续失败或状态异常时停下来等人，不要无限重试
- 自动化只覆盖「**触发 + 传话**」，**不覆盖「验收」** —— `accepted` 永远只有 Lo 能写
