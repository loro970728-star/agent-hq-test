## 一、⚠️ 主要空白：熔断防不了「错判」

### 熔断能抓什么

小咩的三条熔断（连续失败 ≥2、非法跃迁、fetch 失败 ≥5）和 Codex 的对应机制，针对的都是**程序异常** —— 跑挂了、跑不动了、状态乱了。

### 熔断抓不到什么

**程序正常跑完，但复核结论是错的。**

**我有现成的实例：**

> 2026-10-09，我在回复 Lo 之前做了一次文档残留检查，命令写的是：
>
> ```
> grep -n "保持 done" work/claude-code/README.md
> ```
>
> 但原文其实是 `` 保持 `done` ``（**done 外面有反引号**），所以**没匹配上**。
> 我把「没匹配到」当成了「已经修好了」，向 Lo 报告 **「✅ P4 已修」**。
>
> 实际残留仍在。是 Lo 让我「再看看仓库」时才当场发现的。

**这个错误为什么熔断抓不住：**

| 熔断条件 | 会触发吗 |
|---|---|
| 同一任务连续失败 ≥2 次 | ❌ 没失败，正常返回 |
| 非法状态跃迁 | ❌ 状态没动 |
| watcher fetch 失败 ≥5 次 | ❌ 网络好得很 |
| 运行时间 / 轮次 / 调用上限 | ❌ 一次就跑完，很省 |

**它是「安静地跑对了流程、得出了错误的结论」。** 而且如果自动复核出这个错，它会**直接提交 `reviewed` 并通知 Lo「复核通过」** —— Lo 看到的是一个错误的通过，**没有任何告警会响**。

### 建议：复核产出必须附「可验证的证据」，而不只是结论

写进 V2：

> **复核结论必须附带可独立复核的证据（命令原文 + 实际输出），不得只给结论。**

对照两种写法：

| ❌ 只有结论 | ✅ 附证据 |
|---|---|
| 「hello.py 可运行」 | 附实测输出 + 命令原文 + 退出码 |
| 「P4 已修」 | 附 `grep` 命令原文 + 实际输出 |

**这样 Lo 验收时看到的是证据，而不是一句「我检查过了」。**

> **附带说明**：这条**对人工复核同样适用**。上面那个错误就是人工犯的 —— 证据留痕能让人（或下一个 agent）事后复核复核者本身。

## 二、附带观察：这是「半条流水线」

自动化覆盖的范围是 **`done → reviewed`**。但 **Codex 那一端仍然需要 Lo 点火**（说「开工」）。

所以自动化实现后，Lo 的角色是：

| 环节 | 谁 |
|---|---|
| 创建任务 | Lo（或小咩代笔） |
| **触发 Codex 开工** | **Lo** ← 仍是人工 |
| 执行 | Codex |
| **复核** | **watcher 自动触发** ← 这是新增的 |
| 汇总 | 小咩 |
| 验收 | Lo |

**即：Lo 从「全程在线」变成「两头各出一次场」** —— 这已经是大改善，但**不是全自动**。

### 一个值得问 Codex 的问题

> **Codex 有没有无头 / 非交互模式？**
>
> 如果有，watcher 就能在发现 `status: todo` 的新任务时自动触发 Codex，把流水线再往前延伸一环 ——
> 那样 Lo 就只剩「验收」一处出场了。
>
> （如果没有，那就维持现状，不用强求。这条只是提问，不是要求。）

## 四、建议写进 V2 的条目清单

1. watcher 为本机脚本（非 Actions），监听**独立克隆**
2. 通知走 Windows Toast + 本地日志；**禁止提交 NOTIFY 文件**
3. 熔断：按 `任务编号 + done 提交 SHA` 去重；连续失败 ≥2 冻结；非法跃迁立即停
4. **复核产出必须附可验证证据**（本次补充）
5. 自动复核使用专用身份 `Claude Code-auto`
6. 权限双防线：事前路径白名单 + 事后 file list 校验
7. `accepted` 代码层面卡死，任何自动化都不得写入
8. 自动化代码放 `agent-ops`，不混入 `agent-hq-test`
9. 分阶段：手动检测 → 只通知 → 无头复核 → Lo 批准 → 定时启用
