### 关键改进：**必须带验证步骤**

上次失败的原因不是没写清楚，而是**没验证**。建议开工指令里补一条：

```
2. 设置本仓库提交身份（只对本仓库生效，每个 agent 有自己的 clone）：
   git config --local user.name "<你的名字>"
   git config --local user.email "loro970728@gmail.com"

   设置后**必须验证**：
   git config --local user.name      # 应输出你的名字
   首次提交后再核对：
   git log -1 --format='%an <%ae>'   # 应显示 <你的名字> <loro970728@gmail.com>
```

> 说明：`--local` 只影响当前 clone，不会影响其他 agent —— 因为每个 agent 各自克隆。

## 三、验收证据格式规范（观察 2）

T001 的证据标注 `Python: 3.12.14`，但本机可见的解释器是 3.13.14 / 3.12.13，**无法复现**。

结论未受影响（`print()` 与解释器补丁版本无关，实测已确认），但暴露了证据规范问题。

**建议 `AGENTS.md` §4 增加三条**：

1. 记录工具的**完整路径**（如 `where python` 的输出），而不只是版本号
2. 记录**可复现的命令原文**
3. 记录**执行环境**（哪台机器 / 哪个克隆目录）

例：

```
解释器：C:\Users\...\Python313\python.exe  (Python 3.13.14)
命令：  python work/codex/T001/hello.py
目录：  D:\...\agent-hq-test
输出：  Hello, world!
退出码：0
```

**理由**：复核者需要能**独立复现**，而不是只能读自述。

## 四、防复发：单源真相原则

**同一个问题已经出现三次**：

| 轮次 | 改了什么 | 漏了什么 |
|---|---|---|
| v1.1 | 修 §3 的 status 行规则 | 漏了紧邻的 line 34/35 |
| v1.2 | 小咩改名为「秘书」 | 漏了 `README.md`、`plans/README.md` |
| v1.3 | 修 3 处遗留 | 漏了 `work/claude-code/README.md`、`work/codex/README.md` |

**根因**：同一条规则被**复述**在多个文件里。每次改规则要改 N 处，必然漏掉几处。

**建议在 `AGENTS.md` 里新增一节**：

```markdown
## 单源真相

规则只在 `AGENTS.md` 定义一次。

各子目录的 `README.md` 只说明「**本目录放什么**」，
涉及「**规则是什么**」一律写「见 `AGENTS.md`」，不得复述。

理由：复述必过期。历史上已因复述造成三次规则不同步。
```
