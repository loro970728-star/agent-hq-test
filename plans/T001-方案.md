# T001 方案：写一份 Markdown 测试报告

对应任务：`inbox/T001-写一份Markdown测试报告.md`

## 拆解

| 步骤 | 交给谁 | 输入 | 输出 |
|------|--------|------|------|
| 1. 开工 | Lo 对 Codex 说"开工"（通用指令，见下） | — | Codex 自行去黑板认领 |
| 2. 认领任务 | Codex | inbox/ 中 status 为 todo 的任务 | 状态 `todo → in_progress`（单独提交） |
| 3. 执行 | Codex | 任务文件要求 | `work/codex/T001/` 产出 + `evidence/T001/` 证据，状态 `in_progress → done`（单独提交） |
| 4. 复核 | Claude Code | work/codex/T001、evidence/T001 | `work/claude-code/T001/review.md`，状态 `done → reviewed`（单独提交；不通过则追加 `review: rejected` 并回退为 `in_progress` 等待返工） |
| 5. 汇总 | 小咩 | 全仓库 | 验收简报发给 Lo |
| 6. 验收 | Lo | 验收简报 | 状态 `reviewed → accepted`（只有 Lo 能写） |

## 通用开工指令（Lo 复制粘贴给 Codex，全任务通用，不用每次重写）

```
你是 Lo 的执行 agent。以后我说"开工"，你就按以下流程自己去黑板上找活干，不用我再贴详细指令：

1. 进入本地 agent-hq-test 仓库目录（没有就先 clone：https://github.com/loro970728-star/agent-hq-test.git），pull 最新代码
2. 设置本仓库提交身份（只对本仓库生效）：git config --local user.name "Codex"；git config --local user.email "codex@local"
3. 阅读仓库根目录 AGENTS.md 协作公约（v1.3），然后去 inbox/ 找 status 为 todo 的任务，一次只认领一个
4. 认领：把任务文件第一行的 status 改为 in_progress，单独提交并 push（commit message：T00X: todo → in_progress）
5. 按任务文件的要求执行：执行产出写 work/codex/<任务编号>/，验收证据写 evidence/<任务编号>/，任务状态按 AGENTS.md 更新，不碰其他目录
6. 完成：把任务文件状态改为 done，单独提交并 push（commit message：T00X: in_progress → done）
7. 告诉 Lo：哪个任务完成了，产出在哪个目录，证据在哪个目录
```

## 风险点
- 私有仓库 clone 需要 Lo 电脑上的 git 已登录 GitHub（首次需处理一次）。
- Codex 可能一次认领多个任务 → 指令里已限定一次一个。
